## Requirement Quality

#### [REQUIREMENT_CONFLICT] BLOCKER

- Location: `vs-adapter/storage-backend-enum/spec.md:86`, `:87`, `:88`, and `:76`
- Issue: The two-class permission is void, so round-1 blocker 1's fix does not take effect. Clause `:88` reads "neither class SHALL touch a test that asserts S3 behavior itself". Every site both classes name is exactly such a test:
  - CLASS ONE's two sites are inside `extract_bucket_handles_relative_and_absolute_first_entry` (`crates/lakehouse-engine/src/scan/object_store.rs:766-780`), whose whole body asserts S3 bucket derivation — and `:86` compounds it by *requiring* the repointed test to "assert the SAME bucket value it asserts today", i.e. requiring the touch that `:88` forbids.
  - CLASS TWO's site at `crates/lakehouse-engine/src/adapter/connection.rs:485` is inside `storage_block_maps_creds_to_storage_props`, which asserts `endpoint`, `region`, `access_key`, `secret_key`, `session_token`, and `path_style` on the S3 payload. `scan/spec.rs:877` (`s3_props`) and `:963` are helpers feeding S3 assertions; `test_support.rs:64` (`s3_payload`) exists to unwrap an S3 payload for assertion.

  As written, an implementer can satisfy `:86` + `:87` or `:88`, never both, and the plan's central risk control has no consistent reading. A third contradiction sits in the same file: `:76` mandates that the decode-side test "SHALL be EXTENDED rather than replaced", and `plan.md:187` names the extended test `only_matching_lowercase_variant_keys_decode` — a rename plus a new case on the existing `only_the_lowercase_s3_variant_key_decodes` (`crates/lakehouse-catalog/src/storage.rs:239-250`). That edit is neither CLASS ONE nor CLASS TWO, so `:85` declares it invalidates the gate.
- Fix: In `vs-adapter/storage-backend-enum/spec.md:88`, replace "SHALL touch a test that asserts S3 behavior itself" with "SHALL change, weaken, or delete an assertion about S3 behavior", so the clause bans the outcome rather than the file touch, and add "the repointed and completed sites keep every existing S3 assertion byte-identical". In the same scenario, add a CLASS THREE admitting the decode-test extension `:76` mandates, bounded to: keeping every existing payload case, adding only new rejection cases, and changing no existing assertion. Cross-reference `:76` from that class so the two clauses cannot drift apart again.
