## Expert fixes

### crates/lakehouse-engine/src/adapter/pushdown/format/delta_predicate.rs

#### [TACTICAL_SHORTCUT] `predicate_not` negates a possibly-widened child, inverting the drop-under-AND soundness rule

- Location: lines 46-50 (`predicate_not` arm), reached through `fold_and` (lines 63-69) and `translate_between` (lines 289-314)
- Issue: the whole translator rests on the invariant its own doc comment states at lines 6-11 — an untranslatable node widens the surviving file set, never narrows it. `fold_and` implements that by DROPPING untranslatable conjuncts, and `translate_between` by dropping an unconvertible bound. `predicate_not` then wraps whatever came back in `Predicate::not` without checking whether the child was translated exactly or merely widened, and negation inverts widening into narrowing. Concretely, `NOT (ID = 5 AND VALUE LIKE 'x%')` translates as: the inner AND drops the LIKE and yields `id = 5`; the NOT arm returns `NOT(id = 5)`; the kernel then prunes every file whose bounds pin `id` to exactly 5. A row in such a file with `VALUE = 'y'` satisfies the original predicate, so the query loses real rows — a wrong-results defect, not a lost-pruning one, and one that survives the adapter re-applying the full predicate above the scan, because the file is never opened. `NOT (ID BETWEEN 1 AND 'ten')` fails the same way through `translate_between`'s dropped bound, and `FN_PRED_NOT` is advertised in `crates/lakehouse-engine/src/adapter/capabilities.rs:27`, so Exasol does send this node. `not_negates_its_translatable_child` (delta_predicate_tests.rs:127-140) pins the arm's current shape and passes over the wrong behavior, because its child is a bare equality that happens to translate exactly. The same arm exists in `iceberg_predicate.rs:227-230` and was mirrored here without re-deriving its soundness under the drop rule.
- Fix: In crates/lakehouse-engine/src/adapter/pushdown/format/delta_predicate.rs, make exactness explicit rather than assumed. Change the internal walk to return the pair `(Predicate, bool)` where the flag is `true` only when EVERY node under it translated — set it `false` in `fold_and` whenever any child yielded `None`, and in `translate_between` whenever either bound failed to convert; propagate it unchanged through `translate_comparison`, `translate_in`, `fold_or`, `predicate_is_null` and `predicate_is_not_null`. In the `predicate_not` arm, return `None` unless the child's flag is `true`; when it is, return `(Predicate::not(child), true)`. Keep `to_delta_predicate`'s public signature at `Option<Predicate>` by discarding the flag at the top level, so `delta_format_reader.rs` needs no change. Then add tests to crates/lakehouse-engine/src/adapter/pushdown/format/delta_predicate_tests.rs asserting that `NOT` over a `predicate_and` whose second conjunct is a `predicate_notequal` returns `None`, that `NOT` over a `predicate_between` with one unconvertible bound returns `None`, and that `NOT` over a fully-translatable `predicate_and` still returns the negated conjunction — and keep `not_negates_its_translatable_child` as the exact-child case.

#### [TACTICAL_SHORTCUT] Float literals narrow through an unchecked `f64 as f32` cast

- Location: lines 127-129 (`("literal_exactnumeric" | "literal_double", PrimitiveType::Float)`)
- Issue: every other numeric pairing in `literal_to_scalar` refuses a value its target type cannot hold — `i8::try_from(...).ok()`, `i16::try_from(...).ok()`, `i32::try_from(...).ok()` all yield `None`, which fails open to no pruning. The `Float` arm alone uses a bare `f as f32` cast, which rounds silently. When the round goes UP, the translated bound is strictly greater than the requested one, and the resulting predicate is NARROWER than the request: `col > L` becomes `col > R` with `R > L`, so the kernel drops a file whose only qualifying value is exactly `R` even though `R > L` holds. That is the same class of wrong-results failure as the `predicate_not` finding — a lost row, not lost pruning — and it is the one conversion in the function that can produce it. `double_literal_becomes_float_scalar_on_a_float_column` (delta_predicate_tests.rs:288-295) uses `1.5`, which is exactly representable, so nothing currently exercises the rounding path.
- Fix: In crates/lakehouse-engine/src/adapter/pushdown/format/delta_predicate.rs, change the `PrimitiveType::Float` arm to `parse_f64(value).and_then(|f| { let narrowed = f as f32; (f64::from(narrowed) == f).then_some(Scalar::Float(narrowed)) })`, so a literal that does not round-trip through `f32` yields `None` and fails open to no pruning, matching every other numeric arm. Add a test in crates/lakehouse-engine/src/adapter/pushdown/format/delta_predicate_tests.rs asserting that `literal_to_scalar` returns `None` for a `literal_double` value that is not exactly representable as `f32` (for example `0.1234567890123`) against `PrimitiveType::Float`, alongside the existing exactly-representable `1.5` case.

In crates/lakehouse-engine/tests/e2e_unity_test.rs line 1438, assert `embedded_files == 2` against the existing `BASIC_PARTITIONED_ACTIVE_FILES` of 6, keeping the summed-across-shard-fragments wording in the failure message.
