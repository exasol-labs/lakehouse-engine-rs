### crates/lakehouse-engine/src/adapter/pushdown/format/delta_schema.rs

#### [ERROR_AS_CONTROL_FLOW] Column refusal is an expected classification outcome signalled as an error and immediately stringified into data
- Location: `delta_type_to_arrow_tag` return type `Result<String, UdfError>`; `build_delta_table_schema`'s `Err(error) => { refused_columns.push(RefusedColumn { reason: error.to_string(), … }); continue; }` arm; the four `*_refusal` builders
- Issue: refusing a column is a normal, expected outcome of classifying a Delta schema — `build_delta_table_schema` itself documents that "a refused column never fails this call by itself". It is nonetheless signalled with `UdfError::User`, caught one line later, converted back to a plain `String` with `.to_string()`, and stored as data. Guardrails: "Errors signal exceptional conditions, not control flow." The consequence is not cosmetic: `build_delta_table_schema` now has two different meanings for `UdfError` in one loop body — a classification outcome from `delta_type_to_arrow_tag` (recoverable, becomes data) and a genuine malformed-annotation failure from `binding_key` (propagated) — distinguished only by which call produced it. The recursive `array` arm compounds this by using `?` to propagate a non-failure.
- Fix: In crates/lakehouse-engine/src/adapter/pushdown/format/delta_schema.rs, introduce `enum ClassifiedDeltaColumn { Tag(String), Refused(String) }` and change `delta_type_to_arrow_tag` to return it directly (no `Result`), renaming it `classify_delta_type`. Have the four `*_refusal` builders return `String` instead of `UdfError`. In the `DataType::Array` arm, match on the recursive call and propagate `Refused` unchanged (composed per the CONTEXTLESS_ERROR fix) rather than using `?`. In `build_delta_table_schema`, match the classification and push `RefusedColumn { reason }` on `Refused` without any `UdfError` round trip, leaving `?` on `binding_key` as the loop's only error path. Update crates/lakehouse-engine/src/adapter/pushdown/format/delta_schema_tests.rs — `refusal_message`, `binary_struct_map_and_variant_are_refused_with_their_own_reason_citing_350`, and `an_array_inherits_its_element_types_refusal_at_any_nesting_depth` — to read reasons off the refused list without `user_message`.
