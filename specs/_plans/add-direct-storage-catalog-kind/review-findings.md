### crates/lakehouse-engine/src/adapter/connection.rs

#### [SHRINKABLE] The rejected-field loop matches a string against a const array and needs an `unreachable!` arm to compile
- Location: lines 141-148 (`DIRECT_STORAGE_REJECTED_FIELDS`), lines 162-180 (the loop)
- Issue: `validate_direct_storage_preconditions` iterates a `[&str; 6]` const and re-matches each element as a string to decide which `creds` field it stands for, with `_ => unreachable!("DIRECT_STORAGE_REJECTED_FIELDS lists only the fields matched above")` to satisfy exhaustiveness. - Fix: In crates/lakehouse-engine/src/adapter/connection.rs, delete the `DIRECT_STORAGE_REJECTED_FIELDS` const and the `for field in DIRECT_STORAGE_REJECTED_FIELDS` loop including its `unreachable!` arm. Replace them in `validate_direct_storage_preconditions` with a straight sequence that pushes onto `rejected` directly — `if !creds.warehouse.is_empty() { rejected.push("warehouse"); }`, `if creds.token.is_some() { rejected.push("token"); }`, and likewise for `client_id`, `client_secret`, `oauth2_server_uri`, `scope`, `use_sigv4`, and `use_vended_credentials` — keeping the existing error text and field order so `direct_storage_rejects_every_catalog_auth_and_vending_field` and `direct_storage_rejects_use_sigv4_and_use_vended_credentials_when_true` stay green.

The `ListingTableUrl` derivation additionally pulls a DataFusion query-engine type into the adapter's discovery path for a string operation the seam already answers.

#### [UNTESTED_ERROR_PATH] `resolve_columns` fails the entire refresh on a legal timezone-aware Parquet column, and the plan path applies no equivalent check
- Location: lines 147-171, specifically the lossless guard at lines 157-164; the asymmetric plan-path site is `adapter/pushdown/format/parquet_format_reader.rs` lines 131-145 (`logical_schema`)
- Issue: `resolve_columns` substitutes `Utf8` only when `needs_json_fallback(field.data_type())` is true, then requires `arrow_type_from_tag(&arrow_type_to_tag(&declared)) == declared` and returns `UdfError::User("column '…' has Arrow type …, which the scan-spec tag vocabulary cannot represent losslessly")` otherwise. `compatible_exasol_type` admits `DataType::Timestamp(_, _)` for ANY timezone label (`types/mapping.rs` line 69), so `needs_json_fallback` returns false for `Timestamp(Microsecond, Some("America/New_York"))`; `arrow_type_to_tag` renders `"timestamptz_us"`; and `arrow_type_from_tag` returns `Timestamp(Microsecond, Some("UTC"))` (`types/mapping.rs` lines 517-518), which is not equal. The tz normalization is deliberate and documented in `mapping_tests.rs` ("the tag intentionally discards which specific tz string an Arrow input carried"), which means this guard treats an intended, lossy-by-design normalization as an error. The input is reachable: `ArrowReaderMetadata::load_async` with default `ArrowReaderOptions` restores the original Arrow schema from a Parquet file's `ARROW:schema` key-value metadata, so a file written by Arrow or Spark with a non-UTC session timezone carries a non-UTC label. The result is that one such column fails `CREATE VIRTUAL SCHEMA` and `REFRESH VIRTUAL SCHEMA` for the whole schema with an internal-sounding message naming no file and offering no remedy. The plan path is inconsistent with it: `logical_schema` renders the same tag with no lossless check at all, so the same column would have planned fine. No test exercises the `Err` branch — `grep` for "losslessly" finds the production string and no test.
- Fix: In crates/lakehouse-engine/src/adapter/direct_storage.rs, make the two paths agree by normalizing rather than refusing. Replace the `if arrow_type_from_tag(&tag) != declared { return Err(...) }` guard in `resolve_columns` with a re-read of the tag — compute `let tag = arrow_type_to_tag(&declared);` and use `arrow_type_from_tag(&tag)` as the declared type from that point on — so a type the vocabulary normalizes (a non-UTC timezone label) is declared at its normalized form exactly as `logical_schema` plans it, and only a type that renders to the `"utf8"` fallback tag reaches the JSON VARCHAR path. Change `resolve_columns`' return type to `Vec<CatalogColumn>` if no failure mode remains, and drop the `?` at its call site in `list_tables`. Add a test in `crates/lakehouse-engine/src/adapter/direct_storage_tests.rs` named `a_non_utc_timezone_column_is_declared_at_its_normalized_tag` over a fixture footer declaring `Timestamp(Microsecond, Some("America/New_York"))`, asserting the enumerated column carries `ColumnSourceType::Parquet("timestamptz_us")` and that `parquet_format_reader`'s `logical_schema` renders the same tag for the same footer.
