## Premortem

Six months from now this plan failed badly. Three concrete reasons:

1. A Spark job writes `k=__HIVE_DEFAULT_PARTITION__/` for each NULL partition value and also stores `k` in the file. The seam fills every file's map before the fold, so a default-valued segment and a missing segment both hold `None`. The implementer checks the value, and `REFRESH` fails on a valid layout. A second implementer checks key presence instead, the check never fires, and a segment-less backfill file reads NULL with no error. Routed to Requirement Quality `[COMPLETENESS_GAP]`.
2. An operator sets `MERGE_SCHEMA = 'FALSE'` on a table that holds a backfill file with no `k=` segment. The seam reads one footer, so it cannot see that the backfill file stores `K`. That file's `K` reads NULL, and `WHERE K = '1'` prunes it. This is the outcome the user rejected. Routed to Requirement Quality `[REQUIREMENT_CONFLICT]` (HUMAN).
3. The first E2E run goes red. `partition_key_colliding_with_a_parquet_column_overrides_it` fails at `CREATE VIRTUAL SCHEMA`, because its base path also holds the failing `collision_missing_segment/` table. The implementer scopes it with `NAMESPACE`, which makes `k=1` the table name and deletes the override from the test. Routed to Feasibility `[UNSTATED_ASSUMPTION]`.

## Requirement Quality

#### [COMPLETENESS_GAP] BLOCKER: the planned per-file state cannot tell a default-valued segment from a missing one
- Location: `plan.md` tasks 1.2, 1.3, and 1.4, and the Architecture steps 3 and 6. `vs-adapter/direct-storage-hive-partitioning/spec.md` § "A table's partition columns are the union of its files' keys" (third AND step), § "A partition key that names a Parquet column overrides it", and § "A file missing the colliding key's segment fails the refresh".
- Issue: The missing-segment rule asks whether a file's own path carries the `k=` segment. Task 1.3 fills every file's `partition_values` map with every declared key, and stores `None` where the path lacks the segment. Task 1.2 also stores `None` for `k=__HIVE_DEFAULT_PARTITION__` and for `k=`. Task 1.4 runs after the fill (Architecture step 3, then step 6). The only planned per-file state therefore holds the same `None` for a file under `k=__HIVE_DEFAULT_PARTITION__/` and for a file with no `k=` segment. A check on the value fails the refresh for the first file, although the override scenario says that file reads NULL from its segment. A check on key presence never fires, because the fill makes every key present, and the segment-less file then reads NULL with no error. That is the outcome the user rejected. Spark writes `__HIVE_DEFAULT_PARTITION__` for every NULL partition value, so this is a common layout for the writers the override targets. No fixture or unit test covers a default-valued or empty segment on a colliding key.
- Fix: In `plan.md` task 1.2 or 1.3, state that the seam records, per file, the set of keys its own path carries, before the fill. In task 1.4, test that set, not the map value. In the feature spec, add this AND step to "A file missing the colliding key's segment fails the refresh": "a file under `k=__HIVE_DEFAULT_PARTITION__/` or `k=/` carries the segment, so it SHALL read `K` as NULL under the override and SHALL NOT fail the statement". Add both values as cases to `a_key_folding_onto_a_column_drops_the_column_and_keeps_the_key`. Add a case to `a_file_missing_the_colliding_keys_segment_fails_the_fold_naming_it` that proves the filled map alone does not suppress the failure.
- Escalation: MECHANICAL

#### [REQUIREMENT_CONFLICT] BLOCKER: the missing-segment failure cannot run under `MERGE_SCHEMA = 'FALSE'`
- Location: `vs-adapter/direct-storage-hive-partitioning/spec.md` § "A file missing the colliding key's segment fails the refresh", § "A table's partition columns are the union of its files' keys" (the `MERGE_SCHEMA = 'FALSE'` step), and § "Two partition keys that fold to the same name fail the refresh". Seam delta § "The merge mode selects every footer or exactly one". `plan.md` task 1.4. `decision-log.md` [7].
- Issue: The failure rule applies to a file that "also carries the stored column `K`". Only a footer shows whether a file carries `K`. Under `MERGE_SCHEMA = 'FALSE'` the seam "SHALL read EXACTLY ONE footer". The seam sorts paths by byte order (`parquet_directory.rs:120`), so `collision_missing_segment/k=1/p1.parquet` is the sampled file. The seam declares `k` from that file's path and drops the sampled `K`. It never reads `p2.parquet`'s footer, and it fills that file's `k` with `None`. The stored `42` in `p2.parquet` then reads NULL with no error, and `WHERE K = '1'` prunes that file. That is the rejected outcome. The union scenario's `'FALSE'` step points the other way: "a divergent layout degrades to NULL values and ignored keys and MUST NOT fail a query". The same gap affects the two-keys scenario. Under `'FALSE'`, a `Year=` key that only unsampled files carry is ignored, so "SHALL fail" does not hold. Task 1.4 and decision [7] name no merge mode, and no test runs a collision under `'FALSE'`. Escalation is HUMAN because each option changes what a `MERGE_SCHEMA = 'FALSE'` user gets back: NULL rows or a failed statement. The user decided the fold-every-file case live and did not decide this mode.
- Fix: Ask the user which rule holds under `MERGE_SCHEMA = 'FALSE'` when the sampled file stores a column that folds onto a key from its own path. Option (a): a file without that key's segment reads the column NULL, as the documented `'FALSE'` one-layout precondition already allows. Option (b): any file without the segment fails `CREATE`/`REFRESH`. Option (b) needs a path check only and no extra footer read. It also matches DuckDB's default binding, which takes the first file's schema and checks the path of every other file (`multi_file_reader.cpp` lines 316-337). Write the answer as an AND step in "A file missing the colliding key's segment fails the refresh", and scope that scenario's GIVEN to the chosen mode or modes. Update task 1.4, decision [7], and the `docs/catalogs.md` paragraph in task 2.8 to match. Whatever the answer, scope "Two partition keys that fold to the same name fail the refresh" to `MERGE_SCHEMA` TRUE, and state that under `'FALSE'` the check covers only the sampled file's keys, per the union scenario. Add one unit test for the chosen `'FALSE'` behavior.
- Escalation: HUMAN
