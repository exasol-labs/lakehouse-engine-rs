## Components

- udf-entry-points (crates/lakehouse-engine/src/lib.rs): exports the four UDF entry points of the single `.so` (VS adapter, `LAKEHOUSE_SCAN`, `LAKEHOUSE_VERSION`, `LAKEHOUSE_EXPORT`) | owns: engine version string | depends on: vs-adapter, datafusion-scan, export
- vs-adapter (crates/lakehouse-engine/src/adapter/): answers Exasol Virtual Schema requests, reads the CATALOG_CONNECTION, lists the catalog tables the table filter exposes into virtual tables with one identifier note per table and one source note per column, answers a `REFRESH TABLES` by listing catalog identifiers and loading only the requested tables the table filter exposes, and routes pushdown requests through each virtual schema's statement state | owns: schema-level adapterNotes and their format (SKIPPED_TABLES, CATALOG_PREFIX), written and read in adapter/mod.rs; the statement state (§ Constraints); the engine-side scan load that each catalog kind's client implements | depends on: capabilities, vs-properties, table-filter, lakehouse-catalog, pushdown-planner, table-identity, column-notes, type-mapping, sealed-storage
- capabilities (crates/lakehouse-engine/src/adapter/capabilities.rs): holds the advertised capability list, parses the `EXCLUDED_CAPABILITIES` entry list, and answers getCapabilities with the advertised list less the excluded names | owns: advertised capability list, `EXCLUDED_CAPABILITIES` entry syntax | depends on: none
- vs-properties (crates/lakehouse-engine/src/adapter/properties.rs): declares every virtual schema property name and the value rule of each tuning property, applies the table-filter value rule to `TABLE_INCLUDE` and `TABLE_EXCLUDE` and the advertised-name rule to `EXCLUDED_CAPABILITIES`, parses every property once per request, rejects unknown names and invalid values in one error for createVirtualSchema, refresh, and setProperties, reads a rejected value as absent for pushdown and getCapabilities, and parses each tuning value into a fixed-width typed value and the two pattern lists into one table filter; it parses properties only, never adapterNotes | owns: VS property catalog (names and tuning value rules) | depends on: table-filter, capabilities
- table-filter (crates/lakehouse-engine/src/adapter/table_filter.rs): parses the `TABLE_INCLUDE` and `TABLE_EXCLUDE` glob pattern lists and decides whether a virtual table name is exposed, with exclude winning over include | owns: table pattern syntax and the exposure rule | depends on: none
- pushdown-planner (crates/lakehouse-engine/src/adapter/pushdown/): classifies the pushdown request shape (row scan, top-N, single-group aggregate, grouped aggregate, COUNT DISTINCT, join, fallback wrapper), reads each involved table's catalog identifier from its identifier note and its declared schema from its column notes, and renders the dispatch SQL that carries one scan spec per shard; it builds one per-column type map per involved table when it resolves the table, and every type check, binary comparison, and projection reads that map | owns: dispatch SQL, per-shard scan specs, the per-column type map (each column's Exasol type and raw-byte layout, keyed by relation alias and column) | depends on: format-readers, table-identity, column-notes, sharding, type-mapping, vs-expression, scan-spec, sealed-storage, lakehouse-catalog
- format-readers (crates/lakehouse-engine/src/adapter/pushdown/format/): declares each catalog-listed table's columns at createVirtualSchema from the neutral table metadata the catalog client returned, and at pushdown opens one table's filter-independent state (Iceberg metadata, Delta snapshot, Glue partition list, or Parquet directory listing) for Iceberg, Delta, catalog Parquet, and direct-storage Parquet tables when a catalog client loads the table, then prunes its file list per reference with the reference's filter against the declared schema, failing a query whose declaration disagrees with the table's current schema or log | owns: none | depends on: column-notes, lakehouse-catalog, type-mapping
- table-identity (crates/lakehouse-engine/src/adapter/table_identity.rs): encodes each virtual table's identifier note, a table-level adapterNotes JSON object whose `name` member holds the catalog identifier, and reads the identifier back from an involved table at pushdown | owns: table identifier note format | depends on: lakehouse-catalog
- column-notes (crates/lakehouse-engine/src/adapter/column_notes.rs): encodes, size-checks, and parses the per-column declaration notes, and holds the refused-column type and the refusal helpers the declaration builders share | owns: column note format | depends on: scan-spec
- sharding (crates/lakehouse-engine/src/adapter/sharding.rs): computes the shard count G and partitions the file list into G byte-balanced shards | owns: none | depends on: scan-spec
- scan-spec (crates/lakehouse-engine/src/scan/spec.rs): defines the format-neutral JSON wire format between the adapter and the scan UDF (`CommonScanSpec`, `FileEntry`, `LogicalField`, `ScanStorage`) | owns: scan spec wire format | depends on: lakehouse-catalog
- sealed-storage (crates/lakehouse-engine/src/scan/sealed.rs): encrypts storage credentials into the scan spec with AES-GCM under a key derived by HKDF-SHA256 from the CONNECTION password, and decrypts them in the scan UDF | owns: sealed storage envelope format | depends on: none
- datafusion-scan (crates/lakehouse-engine/src/scan/): runs one shard per invocation as a raw scan, a partial aggregate, or a broadcast join scan, applies Iceberg positional deletes and Iceberg and Delta deletion vectors, and emits results batch by batch | owns: per-invocation Tokio runtime, DataFusion session, memory pool | depends on: scan-spec, sealed-storage, scan-object-store, type-mapping, vs-expression
- scan-object-store (crates/lakehouse-engine/src/scan/object_store.rs): builds S3 or ADLS Gen2 object stores with a connection budget and an admission limit, and routes the two join sides by path prefix | owns: per-invocation HTTP connection pool | depends on: lakehouse-catalog
- export (crates/lakehouse-engine/src/export/): validates an `EXPORT ... INTO SCRIPT` statement, checks that the export script can read the CONNECTION and whether the table exists, which decides whether the writers create the table or append to it, renders the writer SELECT that calls the same script with a row-number group key, and, as the writer, matches the source columns to the table's columns by name, writes the rows it receives as Parquet data files, and commits them through lakehouse-catalog-write | owns: export options, writer spec format, Exasol-to-Iceberg type mapping of the export, the column matching and type acceptance of an append | depends on: lakehouse-catalog, lakehouse-catalog-write, type-mapping
- type-mapping (crates/lakehouse-engine/src/types/): maps Arrow, Iceberg, Delta, and Hive types to vs-expression's Exasol SQL type and applies type widening rules | owns: none | depends on: vs-expression
- lakehouse-catalog (crates/lakehouse-catalog/): implements `CatalogClient` for Iceberg REST, Unity Catalog, and AWS Glue (a full listing that drops the identifiers a caller-supplied predicate rejects before it loads any table, an identifier-only listing, and a load of listed tables that classifies each table as the full listing does) with OAuth2, bearer, and SigV4 auth, STS role assumption, vended-storage resolution, and credential redaction, and gives the Unity Catalog and Glue sessions a single-table load outside that trait; its neutral table carries the catalog's table properties verbatim and its neutral column an opaque engine-encoded declaration slot, and it interprets neither | owns: catalog sessions, whose lifetime the adapter decides | depends on: none
- lakehouse-catalog-write (crates/lakehouse-catalog-write/): writes to an Iceberg REST catalog: it creates a namespace level by level (a level is created only when a lookup answers 404), creates a table or stages it for `SINGLE_COMMIT`, and commits a writer's data files onto the freshly reloaded table in one tagged snapshot that asserts the schema ID and partition spec ID the files were written under, reloading the table and checking the tag after a conflict or an unknown outcome so the files land exactly once; it opens each table's FileIO on one renewable credential source per credential kind, and on ADLS Gen2 through its own Iceberg storage over object_store's Azure client, which takes every request's credential from that source | owns: the commit loop and its tag check, the table's write-side credential sources, the ADLS write storage | depends on: lakehouse-catalog
- vs-expression (crates/vs-expression/): translates VS expression JSON into DataFusion SQL and Exasol SQL fragments, parses and rewrites the `column` nodes of a pushdown request, and defines the Exasol SQL type: it reads the type from VS `dataType` JSON, rejects a type outside Exasol's limits, and renders it as Exasol SQL text and as `dataType` JSON | owns: the Exasol SQL type and its SQL and `dataType` JSON renderings | depends on: none
- distribute-files (deploy/scripts/install.sh): defines the Lua SET script `LAKEHOUSE_DISTRIBUTE_FILES`, which re-emits per-shard file-list rows so `GROUP BY shard_key` spreads them across nodes | owns: none | depends on: none
- installer (deploy/scripts/install.sh): downloads the engine and SLC release assets, uploads them to BucketFS with exapump, creates the scripts, and runs a version and fingerprint smoke test | owns: none | depends on: distribute-files

## External Dependencies

- Iceberg REST catalog (including Lakekeeper and Databricks-managed Iceberg): snapshot discovery and file list resolution for Iceberg tables | failure impact: no Iceberg query can be planned or executed
- Lakekeeper management API (`/management/v1/action/batch-check`): the permission check of a virtual schema that sets `PERMISSION_CHECK = 'LAKEKEEPER'` | failure impact: every query of such a virtual schema is refused
- Unity Catalog REST API (`/api/2.1/unity-catalog`, including Databricks): table listing with each table's columns and properties (the source of its column notes), Delta log location, and temporary table credentials | failure impact: no Delta or Unity Parquet query can be planned or executed
- AWS Glue Data Catalog: table listing and routing, Iceberg metadata location, and Hive Parquet partition lists | failure impact: no `GLUE` query can be planned or executed
- Databricks (as Iceberg REST or Unity Catalog endpoint): access to Databricks-managed tables through either catalog kind | failure impact: Databricks queries fail on both routes, and non-Databricks catalogs are unaffected
- OAuth2 token endpoint: client-credentials grant for REST catalog and Unity Catalog authentication | failure impact: same as the catalog it authenticates being unavailable
- AWS STS: session credentials for a CONNECTION that names an IAM role (`aws_assume_role_arn`) | failure impact: every request through that CONNECTION fails, with no fallback to the static base key pair
- S3-compatible object storage: Parquet data files and table metadata files | failure impact: scans fail or stall, and this is a measured bottleneck risk
- Azure ADLS Gen2 (`abfss://`): Parquet data files and table metadata files for Azure-hosted tables, read by scans and written by exports | failure impact: scans of ADLS-hosted tables and exports into them fail
- Forward proxy, when a script's `%env` lines name one: every request to a host outside `NO_PROXY` | failure impact: every such request fails, with no direct fallback
- Exasol cluster, 8.29.x or later, and Rust SLC in BucketFS: UDF execution substrate | failure impact: no execution, and on an older Exasol every pushdown fails the strict type check
- GitHub releases (`exasol-labs/lakehouse-engine-rs`, `exasol-labs/language-container-rs`): engine and SLC assets for install.sh | failure impact: installation fails, and running deployments are unaffected
- exapump: BucketFS upload and SQL execution for install.sh | failure impact: installation fails
