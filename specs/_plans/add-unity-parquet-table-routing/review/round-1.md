## Premortem

1. A Unity Parquet table returns NULLs or truncated numbers where Databricks returns real values. Its catalog declares `CustomerId`, but pandas-written files carry `customerid`. Or newer files carry `double` where the catalog still says `int`. The identity binding matched exact-case only, forced nullability turned the miss into NULL, and the cast ran unchecked. Routes to Requirement Quality, `[COMPLETENESS_GAP]` BLOCKER.
2. A Databricks external table returns rows Databricks does not, or omits rows it returns. Its partition directories start with `_`, or it is a Delta directory registered as `PARQUET`, or it uses partition metadata logging. Routes to Requirement Quality, `[UNSTATED_ASSUMPTION]` and `[COMPLETENESS_GAP]` advisories, plus the Background fix in `[IMPLEMENTATION_LEAKAGE]`.
3. An OSS Unity Catalog Parquet table appears after `CREATE VIRTUAL SCHEMA`, and every query fails with "no mappable column", because its columns carry no `type_json`. This is the appear-then-fail pattern the orchestrator flagged, moved from the format tag to the type descriptor. Routes to Feasibility, `[UNSTATED_ASSUMPTION]` advisory.

#### [UNSTATED_ASSUMPTION] ADVISORY
- Location: `vs-adapter/unity-parquet-table-planning/spec.md` § Scenario "The logical schema is the catalog's declared column list" (absent-`type_json` clause), and `decision-log.md` § Interview Q3
- Issue: The reader types every column from `type_json` alone and refuses a column that lacks it. The createVirtualSchema path maps `type_name` and ignores `type_json`. Such a table therefore lists cleanly and then fails every query with "no mappable column". The Q3 probe POSTed its own column payload. It does not show whether OSS Unity Catalog fills `type_json` for a table that a client registers with only `type_name` and `type_text`. Databricks always sends `type_json`, and `scripts/unity/seed.sh` sends it explicitly.
- Fix: Probe the fixture once with a `POST /tables` whose columns omit `type_json`, and record the echoed shape in `decision-log.md` § Interview Q3. If the server returns no `type_json`, add a bullet to task 2.6: "a Unity Parquet column without `type_json` lists but is refused at query time".

#### [UNSTATED_ASSUMPTION] ADVISORY
- Location: `vs-adapter/unity-parquet-table-planning/spec.md` § Scenario "Partition columns come from the catalog and partition values from the file paths", clause "the scan SHALL convert each value to its partition column's declared type"
- Issue: The shared converter `PartitionedScanSchema::partition_values_for` (`scan/partition_values.rs`) parses each value with `ScalarValue::try_from_string`. A Delta value follows PROTOCOL.md § Partition Value Serialization. A Hive path value follows no protocol. Spark renders a `timestamp` partition value in the writer's session time zone. The converter reads that naive text as UTC for the classifier's `Timestamp(us, "UTC")` tag. A writer outside UTC therefore shifts every timestamp partition value silently. The `INT` partition column of the task 3.1 fixture does not exercise this.
- Fix: Add to that scenario: "*AND* a `timestamp` partition value SHALL be read as UTC, so a value that a writer rendered in another session time zone is shifted by that offset". Add the same sentence as a bullet of task 2.6.

## Requirement Quality

#### [COMPLETENESS_GAP] BLOCKER
- Location: `vs-adapter/unity-parquet-table-planning/spec.md` § Scenario "The logical schema is the catalog's declared column list", clauses "the scan binds it by name through the identity binding already shipped", "every logical field SHALL be declared NULLABLE", and "the scan SHALL cast each file's physical column to the declared type through the existing per-file type-relaxation adapter", and `plan.md` § Non-Goals "A footer-based schema check against the catalog."
- Issue: This reader is the first whose column names and types come from a source that the data files never agreed to. Delta guarantees that file columns match the log. Direct storage derives names and types from the footers. The spec states outcomes only for the matching case and the narrower-physical case, so two drift cases stay silent.
  - Names: `claim_logical` (`scan/field_id_projection.rs:93`) binds by identity with the exact-case test `keys.name == physical.name`. A file column `customerid` under the catalog column `CustomerId` binds nothing, and forced nullability turns the miss into an all-NULL column. Spark resolves Parquet columns case-insensitively by default (`spark.sql.caseSensitive=false`).
  - Types: the column-binding adapter hands every type divergence to `DefaultPhysicalExprAdapter` ("type divergence → cast", `field_id_projection.rs:437`). That adapter applies any arrow-castable pair, not only the `datafusion-scan/type-relaxation` supported set. A `double` file column under an `int` declaration truncates 1.7 to 1, and `timestamp` under `date` drops the time. Spark fails such a file ("Parquet column cannot be converted"). The spec's reference to the type-relaxation adapter implies the bounded, proven pair set, which this path does not have.
  - Escalation is HUMAN: documenting these outcomes and failing loud (Spark-compatible) give a user different results on a drifted table. The Q1 answer ("the catalog establishes the schema") does not settle which one the requester wants.
- Fix: Ask the requester to choose between the two behaviors. For the default choice, which changes no scan code, replace the type-relaxation clause of that scenario with two clauses. First: "*AND* a data-file column SHALL bind only when its name equals the catalog column name exactly, case included, and a column whose name differs only in case SHALL read NULL". Second: "*AND* the reader SHALL NOT compare physical types with the catalog, so a physical type outside identity and the `datafusion-scan/type-relaxation` supported set SHALL be cast by the scan's existing cast, which fails on an unparseable or overflowing value and truncates a fractional value cast to an integer". Add both as trade-off bullets to task 2.6. Pin the case rule with a test in `unity_parquet_format_reader_tests.rs` and list it in Scenario Coverage. If the requester chooses loud failure, plan it as a scan-side change with its own spec delta on `datafusion-scan/scan-execution-field-id-projection`, because every format shares the binding and cast rules.
- Escalation: HUMAN

#### [UNSTATED_ASSUMPTION] ADVISORY
- Location: `plan.md` § Spec compliance, "A Unity Parquet table is not a Delta table: it has no `_delta_log`", and `vs-adapter/unity-parquet-table-planning/spec.md` § Scenario "A Unity Parquet table lists its files through the shared directory seam and reads no footer"
- Issue: The sentence states a definition, not a check. A Delta directory registered in Unity Catalog as `PARQUET` passes admission. The seam's data-file rule skips `_delta_log/` because the segment starts with `_`. The reader then scans every Parquet file, including files the log removed and rows that a deletion vector deletes. Delta Lake's Spark integration refuses this read ("Incompatible format detected"). This plan returns stale rows without an error.
- Fix: Add to that scenario: "*AND* a storage location holding a `_delta_log/` object SHALL fail the plan with an error naming the table as a Delta table registered as `PARQUET`". Check the unfiltered listing for that prefix in task 2.1 or 2.3. Add `a_delta_directory_registered_as_parquet_is_refused` to Scenario Coverage and `unity_parquet_format_reader_tests.rs`.

#### [COMPLETENESS_GAP] ADVISORY
- Location: `vs-adapter/unity-parquet-table-planning/spec.md` § Scenario "A Unity Parquet table lists its files through the shared directory seam and reads no footer", clause "under that seam's data-file rule unchanged", and `data_file_segments` in `crates/lakehouse-engine/src/adapter/parquet_directory.rs`
- Issue: The data-file rule drops a file when any segment below the prefix starts with `_` or `.`. Spark's file index excludes a `_`-prefixed segment only when it contains no `=`, so Spark reads `_part=2024/`. A catalog-declared partition column with a leading underscore therefore makes this reader list zero files and return zero rows, with no error. For direct storage the rule is harmless, because the keys come from the paths. For Unity, the catalog names the key.
- Fix: In task 2.1, exempt from the underscore rule a directory segment whose key matches a declared partition column under the uppercase fold. Add that case to the seam Scenario "The listing answer serves a caller that declares its own partition columns" and to `listing_answer_fills_caller_declared_partition_columns_and_reads_no_footer`. If the planner keeps the rule, state the limitation as a bullet of task 2.6 instead.

## Design Depth

Decision [3] is procedural and correctly `no`. `UnityParquetFormatReader` and `UnityTableStorage` each have a one-sentence responsibility. `UnityTableStorage` hides the no-fallback vending rule behind a smaller interface than its two callers would rebuild. #### [TACTICAL_SHORTCUT] ADVISORY
- Location: `decision-log.md` § [1] Consequences, last bullet, and `plan.md` § Impact, "The skip warning text and the Delta error texts are unchanged."
- Issue: The stated reason is literally true but no longer describes the rule. The admission criterion is now "plannable base table", and the spec deltas use that phrase. - Fix: Add a group A task that changes the Unity arm of `skip_warning` to "createVirtualSchema: skipping unplannable entry '{}' ({})" and updates `skip_warning_renders_the_legacy_iceberg_line_and_the_unity_detail_line`. #### [INFORMATION_LEAKAGE] ADVISORY
- Location: `plan.md` § Implementation Tasks, task 2.2 ("Give `ensure_table_has_a_mappable_column` a table-kind label parameter ... make it `pub(super)`. Make `parquet_format_reader::file_entry` `pub(super)`.")
- Issue: The Unity Parquet reader would import a whole-table guard from the Delta reader module and a file-entry builder from the direct-storage reader module. Both helpers are format-neutral. The guard reads only `LogicalField` and `RefusedColumn`, and `file_entry` reads only `ParquetFile`. Leaving them inside two sibling readers makes each reader module a dependency of another reader.
- Fix: In task 2.2, move `ensure_table_has_a_mappable_column` and `file_entry` into `format/mod.rs`, beside `RefusedColumn` and `ResolvedScan`. Keep the Delta error text byte-identical through the label argument.
