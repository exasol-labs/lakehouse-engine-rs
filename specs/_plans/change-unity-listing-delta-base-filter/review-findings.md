### crates/lakehouse-catalog/src/client.rs

#### [OUTDATED_COMMENT] `SkipReason` doc claims it carries no catalog-kind identity, but both variants name one
- Location: line 71
- Issue: the doc comment states "Carries no catalog-kind identity", yet the two variants are `NotLoadableIcebergTable` and `NotDeltaBaseTable` — one names the Iceberg catalog kind, the other names the Delta format only the Unity kind produces, and the variants are 1:1 with the two `CatalogKind`s. The property the design actually guarantees is different and weaker: the enum carries no `CatalogKind` *value*, so consumers render wording by matching the reason and never reintroduce a `CatalogKind` match. A reader who trusts the sentence as written will conclude the reasons are kind-free and be contradicted by the next two lines.
- Fix: In `crates/lakehouse-catalog/src/client.rs`, rewrite the second paragraph of the `SkipReason` doc comment (line 71 onward) to state the guarantee the code actually makes: the enum carries no `CatalogKind` value, the client that decides to skip owns the reason, and consumers render wording by matching the reason so no second `CatalogKind` match site is reintroduced downstream. Remove the "Carries no catalog-kind identity" claim.

#### [MISSING_DOC_COMMENT] `SkipReason::NotLoadableIcebergTable` variant is undocumented
- Location: line 76
- Issue: `NotDeltaBaseTable` documents its `detail` field, but `NotLoadableIcebergTable` on the same public enum carries no doc. Its contract is not self-evident from the name: it is set only by `IcebergRestCatalogClient::resolve_listing` (line 175) when `loadTable` returns a not-loadable-table error, not because the catalog explicitly declared a type. A caller cannot tell from the name what evidence produced the variant.
- Fix: In `crates/lakehouse-catalog/src/client.rs`, add a doc comment to the `SkipReason::NotLoadableIcebergTable` variant at line 76 stating that the Iceberg REST catalog listed the identifier but `loadTable` reported it is not a loadable Iceberg table, so the entry is skipped rather than failing the whole enumeration.

## Expert fixes

### crates/lakehouse-catalog/src/unity/client.rs

#### [INFORMATION_LEAKAGE] `delta_base_skip_reason` re-states the `VIEW` wire literal instead of receiving it
- Location: line 323
- Issue: the raw Unity `table_type` vocabulary now has two homes in this module. `neutral_table_type` (line 290) owns the mapping `"VIEW" => CatalogTableType::View`; `delta_base_skip_reason` receives the already-lossy `&CatalogTableType` and reconstructs the wire value as the hardcoded literal `"table_type=VIEW"` at line 323. Nothing enforces agreement between the two. The function's own doc at line 310 claims "The returned detail names the offending wire value verbatim" — true for the `Other(raw)` arm, false for the `View` arm. Failure scenario: a later change adds `"MATERIALIZED_VIEW" => CatalogTableType::View` to `neutral_table_type`; a materialized view is then skipped with the operator warning `... (table_type=VIEW)`, naming a value the catalog never sent, while `delta_base_skip_reason_type_wins_over_format_for_a_view_even_when_delta` keeps passing because it asserts on the neutral variant, not the wire value. The operator is handed a wrong diagnosis with no test to catch it.
- Fix: In `crates/lakehouse-catalog/src/unity/client.rs`, change `delta_base_skip_reason` (line 311) to take the raw wire value as its first parameter — `fn delta_base_skip_reason(raw_table_type: &str, data_source_format: Option<&str>) -> Option<SkipReason>` — and call `neutral_table_type(raw_table_type)` inside it. Match the resulting neutral type: `CatalogTableType::Table` with `data_source_format == Some(DELTA_DATA_SOURCE_FORMAT)` returns `None`; `CatalogTableType::Table` otherwise formats `data_source_format={…}` with `ABSENT_DATA_SOURCE_FORMAT` as the fallback; every other variant formats `table_type={raw_table_type}` in a single arm, deleting the hardcoded `"table_type=VIEW"` literal and the separate `Other(raw)` arm. In `list_tables`, delete the now-redundant `let table_type = neutral_table_type(&info.table_type);` at line 216 and call `delta_base_skip_reason(&info.table_type, info.data_source_format.as_deref())` directly. Update the six `delta_base_skip_reason_*` tests in `crates/lakehouse-catalog/src/unity/client_tests.rs` to pass raw strings (`"MANAGED"`, `"VIEW"`, `"STREAMING_TABLE"`) instead of `&CatalogTableType::…` values, keeping every asserted `detail` string unchanged, and add a test that a raw `table_type` mapping to `View` is reported by its own raw spelling.

### crates/lakehouse-engine/src/adapter/mod.rs

#### [MIXED_ABSTRACTION_LEVEL] Warn-message formatting inlined into the createVirtualSchema orchestrator
- Location: lines 288-307
- Issue: `handle_create_virtual_schema` is a 108-line orchestrator whose steps are high-level (resolve connection config, construct the client, list tables, build the virtual-table list, build adapterNotes, build the response). The change drops a two-arm `match` with two long literal message templates into the middle of it, so the function now both decides the flow and renders operator-facing text. It also leaves the byte-identical Iceberg warning — a normative invariant recorded in `vs-adapter/pushdown-catalog-session` and restated in this plan's Design > Context — pinned by nothing but the literal's presence in the orchestrator, since `udf_log!` output is not captured by any test and no test names either string. Extracting the render into a pure function both restores one abstraction level and creates the seam that makes the invariant assertable without any log-capture infrastructure. `crates/lakehouse-engine/src/scan/mod.rs:306` already uses the `udf_log!(ctx, level, "{}", value)` form, so this is the established pattern in this codebase.
- Fix: In `crates/lakehouse-engine/src/adapter/mod.rs`, add a private free function `fn skip_warning(entry: &SkippedTable) -> String` that matches `entry.reason` and returns, for `SkipReason::NotLoadableIcebergTable`, the string formatted from `"createVirtualSchema: skipping non-Iceberg table '{}' (catalog reported it is not a loadable Iceberg table)"` with `catalog_identifier_string(&entry.ident)`, and for `SkipReason::NotDeltaBaseTable { detail }` the string formatted from `"createVirtualSchema: skipping non-Delta-base entry '{}' ({})"` with `catalog_identifier_string(&entry.ident)` and `detail`. Both templates MUST be copied byte-for-byte from lines 294 and 302 — the Iceberg line is a recorded byte-identical invariant. Give `skip_warning` a doc comment stating that the wording is chosen from the entry's neutral reason and never from the catalog kind, which this side of the pipeline never learns. Replace the loop body in `handle_create_virtual_schema` with `udf_log!(ctx, warn, "{}", skip_warning(entry));`. Then add `#[test] fn skip_warning_renders_the_legacy_iceberg_line_and_the_unity_detail_line` to `crates/lakehouse-engine/src/adapter/adapter_tests.rs` asserting the exact full output string for one `SkippedTable` of each `SkipReason` variant, using `cat_ident(&["prod", "finance"], "hive_events")` for the Iceberg case and a `NotDeltaBaseTable { detail: "table_type=VIEW".to_string() }` entry for the Unity case.
