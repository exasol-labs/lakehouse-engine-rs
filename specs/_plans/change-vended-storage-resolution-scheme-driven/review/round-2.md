1. **A later slice implements the withdrawn derivation from the spec that survived.** `specs/vs-adapter/storage-backend-enum/spec.md` says under vending `allow_http` "is read off the vended `s3.endpoint`'s scheme"; `pushdown-planning-cloud-credentials` says plaintext requires operator consent. The permanent library asserts both. A catalog vends `s3.endpoint = http://…` and vended STS keys travel in the clear. → BLOCKER 1.
2. **A maintainer restores the preservation backfill from a Background bullet nobody deleted.** The merged spec still says "absence preserves the static values and the Glue vended path is unchanged". A Glue vended failure gets "fixed" by re-adding the backfill the plan removed. → BLOCKER 2.
3. **The join guard ships untested and a later refactor drops it.** Task 3.7's unit test cannot be written where the plan puts it, so the guard has no gate; a broadcast join then reads an ADLS dimension through an `AmazonS3Builder` addressed by the Azure host. → BLOCKER 3.

## Design Depth

#### [INFORMATION_LEAKAGE] ADVISORY
- Location: `plan.md` § Design > Decision (line 54) and task 2.3
- Issue: one transport-consent boolean becomes a positional parameter on six signatures — `resolve_connection_config`, `handle_pushdown`, `plan_join`, `resolve_one_join_side`, `resolve_file_list`, `resolve_vended_storage` — taking `plan_join` to eighteen positional parameters.
