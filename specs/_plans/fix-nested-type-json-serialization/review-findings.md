### crates/lakehouse-engine/src/scan/field_id_projection.rs

#### [INFORMATION_LEAKAGE] The cast diversion and the row-filter-pushdown withdrawal read two different predicates
- Location: field_id_projection.rs line 796; raw_scan.rs lines 315 and 378
- Issue: one decision — "this column is JSON-rendered" — has two owners that answer differently. `ColumnBinding::nested_columns` (line 796) keys the diversion on the PHYSICAL Arrow type, `needs_nested_json_rendering(field.data_type())`, and its doc comment (lines 786-790) states this is deliberate so that *"a nested column whose logical field declares none — a spec authored before the descriptor existed — is diverted just the same"*. `raw_scan::renders_nested_json` (line 315) and therefore both `scan_table_parquet_format` (line 378) and `session_config_for_spec` key on the DESCRIPTOR, `field.nested.is_some()`. For exactly the input the first comment names — a logical-schema spec with no `nested` descriptor over a physically nested column, which `plan.md`'s Migration table promises deserializes unchanged and `spec_tests.rs` pins — the column IS diverted and rendered while `pushdown_filters` stays `true` at both session and table level, which is the measured silent wrong-rows path this plan exists to close: DataFusion approves the pushdown against the `Utf8` logical schema, removes the `FilterExec`, then drops the conjunct against the physical nested schema and returns EVERY row. The spec delta forbids this explicitly: *"the decision SHALL be taken from the presence of a JSON-rendered nested column in the table schema, read through the SAME single owning predicate the cast diversion reads"* — two predicates, not one. A physical type is unavailable before file open, so the descriptor is the only signal both sites can share.
- Fix: In crates/lakehouse-engine/src/scan/field_id_projection.rs, change `ColumnBinding::nested_columns` (lines 791-805) to iterate `self.nested` — the per-file resolutions keyed by logical column name — mapping each to its physical index in `self.renamed_physical`, so the diversion and `raw_scan::renders_nested_json` both key on the declared descriptor; delete the `None => verbatim(field)` fallback and rewrite the doc paragraph on lines 786-790 to state that a descriptor is the single signal and that a physically nested column with no descriptor is left to the delegate, which fails loudly rather than silently losing a predicate. Add a test to crates/lakehouse-engine/src/scan/field_id_projection_tests.rs named `a_nested_physical_column_with_no_descriptor_fails_the_cast_rather_than_rendering` proving that path errors rather than rendering. Then add a test to crates/lakehouse-engine/src/scan/raw_scan_tests.rs asserting that for every logical schema in which `nested_columns` diverts at least one column, `scan_table_parquet_format` returns `pushdown_filters == false` — so the two sites cannot drift again.
