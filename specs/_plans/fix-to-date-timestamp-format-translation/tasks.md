- [x] 1.1 Create `crates/vs-expression/src/datetime_format_tests.rs` with two table-driven unit tests of `chrono_format(format, target) -> Option<String>`, where `target` is `Date` or `Timestamp`. No scenario tag, because the E2E tests of 2.1 and 2.3 prove the scenarios.
  - `translates_supported_formats`: `YYYY-MM-DD` → `%Y-%m-%d` for both targets, also as `yyyy-mm-dd` and `Yyyy-Mm-Dd`; `DD.MM.YYYY` → `%d.%m.%Y`; `YYYYMMDD` → `%Y%m%d`; `YYYY_MM_DD` → `%Y_%m_%d`; `YYYY/MM/DD`, `YYYY,MM;DD`, `YYYY:MM:DD`, and `YYYY MM DD` keep their separators. Timestamp target only: `YYYY-MM-DD HH24:MI:SS` → `%Y-%m-%d %H:%M:%S`; `YYYY-MM-DD HH24:MI` → `%Y-%m-%d %H:%M`; the tails `SS.FF3`, `ss.ff9`, and `SSFF6` after `YYYY-MM-DD HH24:MI:` → `%S%.3f`, `%S%.9f`, `%S%6f`; `HH24:MI:SS YYYY-MM-DD` → `%H:%M:%S %Y-%m-%d`.
  - `declines_unsupported_formats`, one case per decline reason: an unknown element (`DD-MON-YYYY`), unsupported text after the last part (`YYYY-MM-DDX`, the only case that reaches the check after the `find_iter` loop of 1.2), a non-ASCII letter that folds to a supported one under Unicode case folding (`YYYY-MM-DD HH24:MI:ſſ` for `Timestamp`), a `TO_DATE` with a time (`YYYY-MM-DD HH24:MI`), a `TO_TIMESTAMP` with an hour but no minutes (`YYYY-MM-DD HH24`), and a missing `DD` (`YYYY-MM`).
  Both tests fail before 1.2.
- [x] 1.2 Add `regex = { version = "1" }` to the root `[workspace.dependencies]` and `regex = { workspace = true }` to `crates/vs-expression/Cargo.toml`. `Cargo.lock` already resolves `regex` through DataFusion, so the `.so` gains no crate. Add `crates/vs-expression/src/datetime_format.rs`, declared in `lib.rs` as a private `mod datetime_format;`, with `#[cfg(test)] #[path = "datetime_format_tests.rs"] mod tests;`. Implement `chrono_format` with one part regex compiled once, `static PARTS: LazyLock<Regex>` over `(?i-u)\.?FF[369]|HH24|YYYY|MM|MI|DD|SS|[-/.,;:_ ]`, and no separate tokenizer. The regex is the one place that names the supported parts and separators, with a comment of at most 2 lines. `.FFn` comes first, so `.ff3` is one part and joins as `%.3f`, and a lone `.` matches as a separator. The `-u` flag keeps case folding ASCII-only, because Unicode folding matches `ſ` to `S`. Walk `PARTS.find_iter(format)`: `chrono_format` returns `None` when a match does not start where the previous one ended, and when the last match ends before the end of `format`, because skipped text is an unsupported part. Map each part, upper-cased, to its strftime form (a separator maps to itself), count the parts, and apply the structure rule: `YYYY`, `MM`, `DD` once each, and for `Timestamp` the time elements none, `HH24`+`MI`, `HH24`+`MI`+`SS`, or those three plus one `FFn` (decision-log [2]). Give the function a doc comment of at most 2 lines: `None` means no exact strftime equivalent exists, so the caller declines.
