## Feasibility

#### [UNSTATED_ASSUMPTION] BLOCKER
- Location: plan.md task 3 (the two sentences "This task closes it end to end" and "ONE step stays outside this capture by design — that the pushdown request carries the SERVED name rather than the Iceberg one — and capture (1) already established it for ASCII names"); `vs-adapter/pushdown-module-structure/spec.md` Background bullet 79 ("ONE step stays outside the capture: that the pushdown request carries the SERVED name rather than the Iceberg one, which capture (1) establishes for ASCII names"); decision-log.md decision [6] and the round-4 `[plan-review]` entry ("what stays open is one narrower step, that the pushdown request carries the served name, which capture (1) established for ASCII names"); plan.md § Impact paragraph 2 ("task 3 closes the inference as a gate")
- Issue: three defects in one paragraph, and the third puts a false evidentiary claim into the permanent library. (1) **Self-contradiction.** Task 3 says the capture "closes it end to end" and, four sentences later, that "ONE step stays outside this capture by design". Both cannot hold; a reader cannot tell whether the gate discharges the inference or not. (2) **The residual is the wrong one.** Re-derived the reachability arithmetic from scratch: the divergence needs only that the name reaching `involvedTables[].columns[].name` still contains `ß`. If it arrives as `STRAßE` (served), the single-table list holds `to_uppercase("STRAßE")` = `STRASSE` and the join list holds `to_ascii_uppercase("STRAßE")` = `STRAßE`; the guard folds the node name to `STRASSE`, so it resolves single-table and misses on the join. If it arrives as `straße` (Iceberg, unfolded), the two lists are `STRASSE` and `STRAßE` again and the outcome is identical. "Served versus Iceberg" is therefore NOT load-bearing — both branches produce the divergence. The one branch that kills it, a name arriving `ß`-collapsed as `STRASSE`, is the residual the plan needs to name and does not. (3) **The residual is attributed to a capture that cannot bear on it.** Capture (1) is a `SYS.EXA_ALL_COLUMNS` read over `id`, `c_varchar`, `c_decimal_a` — it observes the CATALOG, not the request, and every name in it is ASCII, where the two folds agree. An ASCII catalog read can establish nothing about whether `ß` survives into a request field. Confirmed the repo holds no artifact that could: a sweep of `crates/**/testdata`, `docs/`, and every `.json` in the tree found zero captured live pushdown requests — the only ten `testdata` files are generated-SQL goldens, and every `involvedTables` occurrence is a hand-authored `serde_json::json!` fixture. Task 3's new read shares capture (1)'s channel, so it closes the FOLD question and leaves the catalog-to-request link exactly as unmeasured as before, while bullet 79 — permanent-library text — records it as established.
- Fix: In plan.md task 3, delete "This task closes it end to end." and replace it with a statement that the capture closes ONE of the composition's two links, the fold. Restate the residual as what it is: that the name Exasol places in `involvedTables[].columns[].name` still carries `ß` rather than a collapsed `SS`, which no capture in this plan measures and which capture (1) cannot measure because every name in it is ASCII. Delete the claim "capture (1) already established it for ASCII names" and the "SERVED name rather than the Iceberg one" framing, and state that both the served and the Iceberg form yield the divergence, so only a `ß`-collapsing fold would refute it. Apply the identical correction to `vs-adapter/pushdown-module-structure/spec.md` Background bullet 79, to decision-log.md decision [6]'s Rationale, and to the round-4 `[plan-review]` entry. In plan.md § Impact paragraph 2, change "task 3 closes the inference as a gate" to name the fold link only. If the residual is to be measured rather than named, add the behavioral read the round-4 entry rejected as yielding "no further evidence": a two-table join query over the `straße` column against the existing `MY_LAKEHOUSE_JOIN` virtual schema, whose pushdown declining for `straße` while succeeding for an ASCII column demonstrates the divergence end to end without reading the request field at all — that reason for rejecting it does not hold, since it is the only available observation of the residual.
