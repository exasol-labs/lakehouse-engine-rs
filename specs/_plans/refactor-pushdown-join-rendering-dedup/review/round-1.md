## Summary
- Axes checked: 6/6

## Premortem

Three failure stories, each routed into the taxonomy below.

1. **Six months on, `/speq:audit` reports mission-to-spec drift and nobody can tell which spec is authoritative.** The plan deletes `collect_column_tables` and `render_selectlist_item_qualified`, both of which two *other* recorded features name normatively. Neither feature is in the plan's Features table, so `/speq:record` merges this plan and leaves the library asserting a MUST about a function that no longer exists. → Requirement Quality, BLOCKERs 1 and 2.
2. **A later refactor unifies the two column collectors, silently breaking non-ASCII identifiers, because the plan's cited authority did not say what the plan claimed.** Decision [1] attributes the case-folding prohibition to `specs/_decision/037-refactor-pushdown-collect-walk-dedup.md`, which contains no such statement. That decision is marked `Promotes to ADR: yes`, so the false provenance becomes permanent. → Requirement Quality, BLOCKER 3.
3. **The spec records a one-owner guarantee the refactor never delivered.** The clause-walk scenario promises editing one function to add or remove a clause; task 6.5 requires `referenced_side_columns` to keep its own `selectList` guard, so `selectList` stays named in two functions. → Requirement Quality, BLOCKER 4.

## Feasibility

#### [UNSTATED_ASSUMPTION] ADVISORY
- Location: plan.md § Implementation Tasks, task 1.3
- Issue: the transcription rule is factually wrong. Task 1.3 says to resolve `\`-newline continuations "(the continuation eats the newline and the next line's leading whitespace, leaving a single space)". Rust leaves *nothing* — it strips the newline and all leading whitespace, and the separating space must already precede the backslash. Every one of the six literals relies on that (`"... for the \"`). An implementer following the stated rule literally produces `for the  qualified` with a double space at all six sites. This is the plan's only protection for six otherwise-unasserted error messages.
- Fix: In plan.md task 1.3, replace the parenthetical with "the continuation removes the newline and all leading whitespace on the next line and inserts nothing; the separating space already precedes the backslash in each literal", and add: "if the assertion fails on unmodified HEAD, copy the `left` value from the `assert_eq!` output rather than re-deriving the expected string by hand."

## Design Depth

#### [SHALLOW_DESIGN] ADVISORY
- Location: plan.md § Design → Patterns row 3 and § Key interfaces; task 3
- Issue: `column_tables(expr) -> (HashSet<String>, bool, bool)` fails the plan's own stated criterion — "Each reduction must earn its keep by removing a *decision* that currently lives in two places, not merely by removing lines." The duplicated *decision* is not the four-line declaration; it is the untagged-column test, hand-written at both call sites: `has_untagged || !any_column || tables.len() != 1` in `conjunct_single_side` and `any_column && !has_untagged && tables.iter().all(...)` in `build_n_scan_join_from`. The plan moves the boilerplate and leaves the decision in two places. The chosen return type also introduces a new hazard the `&mut` form did not have: two adjacent same-typed bools in an unlabeled tuple, where a destructuring swap at either call site compiles silently and reroutes side-local conjuncts to the residual WHERE.
- Fix: In plan.md § Key interfaces and task 3.1, replace the tuple with `pub(super) fn single_side_tables(expr: &Json) -> Option<HashSet<String>>`, returning `None` when the expression carries an untagged column or references no column at all, so the shared test lives in the helper. Update task 3.2 to have `conjunct_single_side` reduce to a `filter(|t| t.len() == 1)` and `build_n_scan_join_from` to `leg_index`-membership only. If the tuple form is kept instead, add a decision-log entry naming the bool-swap hazard and the golden test that would catch it.
