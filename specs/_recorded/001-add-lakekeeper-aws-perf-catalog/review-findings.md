### Makefile

#### [SUPPRESSED_WARNING] `lint-lakekeeper-scripts` cannot fail and misreports a lint failure as "shellcheck not installed"
- Location: lines 252-256
- Issue: the recipe is `@command -v shellcheck >/dev/null 2>&1 && shellcheck -s bash <files> || echo "shellcheck not installed locally — skipping"`. When shellcheck IS installed and reports findings, its non-zero exit falls through to the `||` branch, which prints the "not installed — skipping" message and exits 0. - Fix: In the Makefile, rewrite the `lint-lakekeeper-scripts` recipe as an if/else so shellcheck's exit status propagates: `@if command -v shellcheck >/dev/null 2>&1; then shellcheck -s bash deploy/scripts/lakekeeper-provision.sh deploy/scripts/lakekeeper-up.sh deploy/scripts/lakekeeper-down.sh; else echo "shellcheck not installed locally — skipping (no CI job runs it for these scripts)"; fi`. ### deploy/scripts/lakekeeper-provision.sh

#### [CONTEXTLESS_ERROR] A non-`s3://` table location is reported as a mixed-bucket error naming no table
- Location: lines 163-168
- Issue: `buckets="$(jq -r '.[].table_location | capture("^s3://(?<b>[^/]+)/").b' ...)"` — jq's `capture` emits nothing for an input that does not match, so any table whose `table_location` is not an `s3://…/` URL (an `s3a://` scheme, a bare path, a bucket-root location with no trailing slash) is silently dropped from the bucket set instead of being rejected. When every location fails to match, `buckets` is empty and the script dies with `FATAL: table locations span more than one S3 bucket:` followed by an empty list — an error naming neither the real constraint nor the offending table. When only some fail to match, the check passes and those tables are registered against a warehouse prefix derived without them.
- Fix: In deploy/scripts/lakekeeper-provision.sh `derive_bucket_and_prefix`, before the bucket-set computation, select every triple whose `table_location` does not match `^s3://[^/]+/` and, if that set is non-empty, exit 1 with a message naming each offending table and its location and stating that only `s3://<bucket>/<key>` locations are supported. Keep the existing mixed-bucket message for the case where two or more distinct buckets really are present, and include the distinct bucket names in it.

#### [AMBIENT_STATE_READ] Three target-half functions read run-computed URI globals instead of receiving them
- Location: lines 554-571, 597-611, 626-659 (globals set at lines 685-686)
- Issue: `create_namespace`, `confirm_registered_metadata_location`, and `register_table` each take `token` (and, for the latter two, the table name) as explicit parameters but reach into `$TARGET_NAMESPACES_URI` / `$TARGET_REGISTER_URI`, which are assigned at top level only after `resolve_warehouse_prefix` has run. Nothing in the three functions' signatures or doc comments records that ordering contract, so calling one before line 686 aborts on `set -u` with an unbound-variable message rather than a stated precondition. This is the only place in the script where a computed value — rather than a caller-supplied `LK_TARGET_*` — is passed by global.
- Fix: In deploy/scripts/lakekeeper-provision.sh, add the URI as an explicit leading parameter to `create_namespace` (namespaces URI), `register_table` (register URI plus namespaces URI), and `confirm_registered_metadata_location` (namespaces URI); remove the reads of `$TARGET_NAMESPACES_URI` / `$TARGET_REGISTER_URI` from their bodies; and pass the values from the top-level Run section at lines 688 and 696.
