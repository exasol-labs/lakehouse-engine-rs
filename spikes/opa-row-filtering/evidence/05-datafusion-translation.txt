PROBE 6 -- SILENT DIALECT DIVERGENCE (same SQL, different answer)
==============================================================================
-- 6a Trino substring(str, -3) = last 3 chars. DataFusion?
    | OWNER | MASKED    |  | alice | ****alice |  | bob   | ****bob   |  | carol | ****carol |  | dave  | ****dave  |
   Trino would render alice -> '****ice'. Anything else is an UNMASKED leak.
-- 6b regexp_like: SAME NAME, different regex engine
   Trino evaluates it with java.util.regex; DataFusion with the Rust
   `regex` crate. Trino was NOT run here, so these are one-sided results:
   an accepted pattern is only proof that DataFusion answers, not that it
   answers the same as Trino.
      ^(?i)eu-     -> ACCEPTED, matched 4 rows
      \p{Alpha}+   -> ACCEPTED, matched 8 rows
      (?<g>eu)-    -> ACCEPTED, matched 3 rows
      (?=eu)       -> EXEC: Optimizer rule 'simplify_expressions' failed
      (\w)\1       -> EXEC: Optimizer rule 'simplify_expressions' failed
      Lookahead/backreference fail loudly, which is the SAFE outcome.
      The unsafe class is a pattern both engines accept and read differently.
-- 6c clock functions are evaluated INSIDE the shard, once per shard
   shard 0 | D          |  | 2026-09-17 |
   capabilities.rs:117-132 withdrew the now-family precisely because of this:
   "GROUP BY SYSTIMESTAMP over a two-file table returned two distinct timestamps"
